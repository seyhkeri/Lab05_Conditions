## Итоговая таблица: когда использовать конструкции

| Конструкция | Когда использовать |
| :--- | :--- |
| **if/else** | Общее ветвление, сложные логические условия. |
| **else if** | Несколько последовательных взаимоисключающих вариантов. |
| **switch/case** | Сравнение одной переменной с конкретными значениями или паттернами. |
| **Тернарный оператор ? :** | Простой выбор одного из двух значений в одну строку. |
| **&&** | Логическое И (оба условия должны быть истинны). |
| **\|\|** | Логическое ИЛИ (хотя бы одно условие должно быть истинно). |
| **!** | Логическое НЕ (отрицание / инверсия условия). |
| **int.TryParse()** | Безопасное преобразование строки в число без падения программы. |
| **Random.Next(min, max)** | Генерация случайного целого числа в заданном диапазоне. |

## Ответы на контрольные вопросы

### 1. Чем int.TryParse() безопаснее int.Parse()? В каких случаях стоит использовать каждый?
int.Parse() аварийно завершает работу всей программы, если пользователь вместо числа введет буквы. int.TryParse() не роняет программу, а возвращает false, что позволяет вежливо попросить пользователя повторить ввод. int.Parse() можно использовать только тогда, когда мы заранее на 100% уверены, что в строке находится число. Во всех остальных случаях (особенно при обработке ввода из консоли) нужно использовать int.TryParse().

### 2. Когда switch удобнее, чем цепочка if/else if? Приведите пример из реальной жизни.
switch удобнее, когда нужно проверять одну конкретную переменную на соответствие четкому списку готовых значений. Пример из жизни: выбор пункта меню в терминале самообслуживания (Нажмите 1 — Оплата, Нажмите 2 — Проверить баланс, Нажмите 3 — Выход). Код на switch в таких случаях читается гораздо легче, чем цепочка из множества else if.

### 3. Что произойдёт в switch, если убрать break после одного из case?
В C# возникнет ошибка компиляции, и программа не запустится. Язык C# запрещает неявное «проваливание» из одного case в другой в целях безопасности кода (исключением являются только пустые case, идущие подряд для группировки одинаковых условий).

### 4. Чем отличается = от == в C#? Почему это частая ошибка?
Один знак = - это оператор присваивания (записать значение в переменную). Два знака == — это оператор сравнения (проверить, равны ли значения). Новички часто путают их и пишут один знак = внутри условия if, что приводит к синтаксическим ошибкам.

### 5. Можно ли написать тернарный оператор внутри другого тернарного оператора? Приведите пример.
Да, это возможно и называется вложенным тернарным оператором. Пример из кода лабораторной работы:
`string weather = temp >= 20 ? "тепло" : (temp >= 0 ? "прохладно" : "мороз");`
Читаемость такого кода сильно падает. Если вложенность становится глубже одного уровня, код усложняется для восприятия, поэтому в реальной разработке вложенные тернарные операторы рекомендуется заменять на классический if/else.
